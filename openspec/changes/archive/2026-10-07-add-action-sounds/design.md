# Design

## Context

См. `proposal.md` для мотивации. `ActionSection.tsx` содержит строку «Тип» и редактор из реестра `actionTypes`. Единственный текущий тип — `keySequence`. Rust `Action` сериализуется как tagged enum, а `profiles::update_action` заменяет действие целиком после normalize/validate. `KeySequenceEditor` сохраняет шаги через spread текущего action.

`EngineCore::tick` копирует action в `Job` после задержки, executor проверяет отмену и вызывает callback исполнения в `engine.rs`, где запускается `keyboard::run_action`. Это место фактического начала действия. `shutter.rs` уже синтезирует короткий PCM WAV и использует Windows `PlaySoundW`; у этого пути нет управления громкостью отдельного сигнала. Общего UI Slider в проекте пока нет.

## Goals / Non-Goals

**Goals:** единый источник звука для предпрослушивания и исполнения, совместимость JSON, неблокирующее исполнение и ограниченная нагрузка при перетаскивании громкости.

**Non-Goals:** импорт файлов, редактор звуков, системная громкость, озвучка каждого шага и изменение звука затвора. Пустое действие со звуком остаётся неполным для запуска отслеживания.

## Decisions

### 1. Общие настройки action без изменения формы JSON

Расширить `Action` общими полями `sound: { id: SoundId | null, volumePercent: number }`, сохранив существующие `type` и `steps` на верхнем уровне. В Rust выделить общие настройки в оболочку с flattened enum содержимого действия, чтобы следующие типы не дублировали звук. `None` означает «Без звука». `serde` defaults должны покрывать отсутствие объекта sound и отсутствие его отдельных полей: null и 50. Новые сохранения валидируют известный id и целочисленный диапазон 0–100.

Пример: `{"type":"keySequence","steps":[],"sound":{"id":"soft-ping","volumePercent":50}}`.

Обновить создание defaults, сопоставления Rust enum и fixtures. При смене типа `ActionSection` переносит текущий sound в новое default action. Изменения шагов сохраняют sound, изменения звука сохраняют шаги. Альтернатива — поля на Tracker — упрощает enum, но разносит свойства действия между разными API и снимками Job.

### 2. Каталог и синтез в Rust

Новый модуль `action_sound` владеет стабильными id, display names и детерминированным синтезом mono PCM 44.1 kHz. Каталог отдаётся командой `action_sounds_list`, frontend не дублирует список. «Без звука» добавляется UI первым пунктом. На первом использовании PCM каждого звука кэшируется; уровень применяется к копии отсчётов непосредственно перед воспроизведением. Амплитуда нормализуется, огибающие плавно начинают и завершают звук, нет клиппинга и резких срезов.

### 3. Нативный аудиосервис

Общий сервис звука вызывается из команды `action_sound_preview(id, volumePercent)` и из callback executor перед `keyboard::run_action`. Звуки действий отправляются отдельному аудиоработнику, который использует Windows waveOut API и удерживает PCM/header до завершения или корректного сброса и освобождения устройства. Не использовать изменение системной громкости: масштабирование PCM обеспечивает уровень конкретного сигнала. Этот путь не использует `PlaySoundW` затвора.

Сервис имеет ограниченное число активных голосов и не копит очередь прослушивания: новый preview заменяет предыдущий; команды preview обрабатываются последовательно с принципом latest value wins. Runtime сигналы допускают короткое перекрытие, чтобы новый звук запускался вместе с новым действием, не ожидая предыдущего сигнала. При достижении лимита освобождать самый старый runtime голос; preview имеет отдельный слот. Worker освобождает ресурсы и при завершении приложения. Возврат ошибки preview связан с UI-запросом; ошибки runtime логируются без влияния на действие.

Альтернативы: frontend Audio зависит от webview и потребует отдельного runtime пути; `PlaySoundW` с async памятью усложняет безопасную замену буферов и разделение голосов. Синхронное воспроизведение на executor задержало бы клавиши и паузу, поэтому исключено.

### 4. Строка настроек и автосохранение

Порядок: `Тип [select]  Звук [select] [компактный slider]`. В раскрытом меню строка каждого звука содержит название слева и кнопку Play справа; у «Без звука» кнопки нет. Слайдер имеет доступный лейбл «Громкость», tooltip/значение в процентах и ширину около 80–100 px. На обычной ширине тип находится слева, группа звука — у правого края, со свободным пространством между ними; при минимальной ширине разрешён перенос целой группы звука без обрезания контролов. Native range либо тонкий компонент проекта обеспечивает клавиатурное управление без новой UI-зависимости.

Кнопка пункта передаёт id собственного звука и текущую громкость, не меняет сохранённый выбор и не закрывает меню. Нажатие на название выбирает звук обычным образом. Обеспечить раздельную обработку pointer и keyboard активации выбора и preview. Текущий общий SelectItem оборачивает children в ItemText, поэтому нельзя просто вложить туда кнопку: она не должна попадать в текст выбранного значения или конфликтовать с выбором пункта и доступностью. Для звуков создать специализированный popup с раздельными зонами выбора и preview и согласованным управлением фокусом; обычный select типа действия сохраняет своё поведение. В trigger показывать только имя выбранного звука.

Выбор звука сохраняется автоматически, но не запускает preview. Play каждого пункта использует актуальное локальное значение громкости; прослушивание другого пункта не меняет звук, используемый при изменении громкости или исполнении действия. Изменение слайдера обновляет значение немедленно, без предпрослушивания во время движения. Отпускание указателя запускает preview один раз с последним значением; pointer capture сохраняет это поведение при отпускании за пределами слайдера. При управлении клавиатурой preview запускается при отпускании клавиши. Отмена жеста или переход между отслеживаниями сбрасывает незавершённое прослушивание. Новый preview заменяет старый, 0% прекращает слышимый preview. «Без звука» отключает слайдер, сохраняет громкость и останавливает текущий preview через команду stop; в открытом меню другие звуки можно прослушивать, даже когда выбран «Без звука».

Записи action упорядочивать в пределах отслеживания: не отправлять параллельные замены из устаревшего action. Пока предыдущая запись выполняется, объединять следующие изменения в последний желаемый снимок со всеми актуальными шагами и sound. После завершения отправлять актуальный снимок; UI не откатывается к промежуточным ответам. При переходе между отслеживаниями сбросить незавершённый preview и завершить сохранение для исходного id. Ошибка сохранения видима, желаемое значение допускает повтор, сохранённое значение не считается обновлённым.

### 5. Момент воспроизведения и снимок очереди

Сохранить существующую семантику `Job.action`: настройки копируются при постановке в очередь. Уже ожидающий Job использует прежний звук и громкость. Обновления действуют для следующих постановок, включая ожидание предзадержки до копирования. Запуск звука происходит после проверки отмены и снятия capture pause, один раз до исполнения клавиш. Не добавлять frontend listeners для runtime playback и не менять расчёт `ActionDone`.

## Risks / Trade-offs

- [Устаревшая замена action при быстрых изменениях] → Упорядочить записи всего действия и проверить пересечение редактирования шагов и громкости.
- [Небезопасное освобождение нативного буфера] → Worker владеет PCM/header, освобождает их только после завершения/reset; проверить повторные preview и shutdown.
- [Похожее звучание или разная воспринимаемая громкость] → Нормализация, разные огибающие/тембры/ритмы и ручное прослушивание всех 20 вариантов.
- [Недоступное аудиоустройство] → Видимая ошибка preview; runtime продолжает исполнение и допускает восстановление устройства для следующих сигналов.
- [Частые срабатывания] → Ограниченные голоса и вытеснение старого сигнала без задержки executor; audioservice не имеет неограниченной очереди.

## Migration Plan

Добавить serde defaults и проверить загрузку существующего JSON версии 1 до подключения UI. Номер версии конфига не меняется: поля additive, старые профили сохраняют шаги и состояние запуска. После первого изменения сохраняется расширенный объект action. Обновить frontend, backend и fakeBackend согласованно. При откате старый serde игнорирует новые поля, но последующее сохранение старой версией может потерять звуковые настройки.
