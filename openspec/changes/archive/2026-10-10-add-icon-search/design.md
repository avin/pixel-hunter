# Design

## Context

См. мотивацию в `proposal.md`. Приложение использует React/Redux и Tauri/Rust для Windows. `Tracker` хранит `pixels` и вариант `pixels | hotkey`; готовность визуального варианта сейчас зависит от непустого списка пикселей. `EngineCore` собирает точки всех опрашиваемых отслеживаний, а `PrimaryScreen.read_pixels` читает их из одного DXGI texture через компактный staging buffer. Опрос идёт раз в 50 мс. Полный `Frame` уже доступен для снимка, но копирует весь монитор в CPU.

Захват пикселя уже имеет подготовленное переиспользуемое окно, отмену, статус и паузу движка. Picker принимает одну точку; viewer и файлы адресуются через `pixelId`. Файлы снимка и миниатюры живут в каталоге профиля. Публичные команды, payload и типы нужно расширять согласованно.

Обнаружено расхождение, не относящееся к этой функции: `pixel-capture` специфицирует отсчёт 3 секунды, тогда как `pixel_capture.rs` использует `COUNTDOWN = 200 мс`. Это изменение не меняет длительность захвата; оба режима используют один существующий процесс. Проверку соответствия тайминга основной спецификации следует учитывать отдельно, не исправляя её скрыто в этой работе. Viewer сейчас использует fitted presentation; прямоугольники следует привязать к координатам исходного изображения, как существующий маркер пикселя.

## Goals / Non-Goals

**Goals:** общий жизненный цикл визуального захвата, проверка пикселей и иконок по одному источнику кадра, обратная совместимость настроек и поставка native зависимости в Windows build.

**Non-Goals:** распознавание семантики эффектов, OCR, автоматическое нажатие по найденной позиции, масштабирование/поворот шаблона, дополнительные мониторы, OR/произвольные булевы выражения. Действие остаётся существующим действием отслеживания, например последовательностью клавиш.

## Decisions

### 1. Иконки внутри существующего визуального варианта

Сохранить `Trigger::Pixels` и добавить `Tracker.icons` с `serde(default)` и зеркальный frontend тип. Каждая иконка содержит UUID, `searchRect`, `templateRect`, `condition: present | absent`, `similarityPercent`. Прямоугольники хранят `x, y, width, height` в физических пикселях, с полуоткрытыми границами. Пути вычисляются из UUID и профиля, не принимаются из пользовательского payload.

Готовность: `pixels.len() + icons.len() > 0` и готовое действие. Удаление последнего визуального элемента останавливает отслеживание; удаление последнего пикселя при оставшейся иконке не останавливает. Хоткей сохраняет оба списка, но не оценивает их. Проверка файлов образца является отдельным состоянием доступности: ошибка блокирует визуальное срабатывание и видна пользователю, не уничтожая настройки.

Альтернатива — новый `Icon` trigger — не позволяет смешивать пиксели и иконки в одном условии. Универсальное дерево предикатов избыточно для существующего AND.

### 2. Общая сессия захвата с явным режимом и этапом

Расширить существующую сессию режимом `pixel | icon` и нейтральным идентификатором элемента в общих внутренних payload. Сохранить совместимость имеющихся команд пикселя либо обновить всех вызывающих в одной поставке. Захват иконки проходит тот же pipeline ожидания игры, подготовки overlay, снимка и затвора; не создавать второй параллельный DXGI capturer. Глобально активна одна сессия обоих режимов, обе кнопки блокируются до её завершения.

После снимка overlay использует состояние `search-area -> template-area -> saving`. Перетаскивание с pointer capture нормализуется независимо от направления. Первое отпускание фиксирует только область поиска; второе завершает захват лишь после backend проверки размеров и вложенности. Не выполнять второй снимок. Нулевые и выходящие за допустимые границы прямоугольники отклонять, показывать причину и оставлять этап активным. Во время drag рисовать контур; после первого шага сохранять рамку поиска. Esc отменяет оба этапа. Плашка инструкции имеет `pointer-events: none`, серый фон и чёрный текст, offset от курсора; у края clamp по viewport. CSS координаты плашки отделить от физических координат изображения.

Альтернатива — независимый редактор иконок — дублирует подготовку окна, паузу и обработку ошибок, уже проверенные захватом пикселя.

### 3. Образец хранится отдельно от снимка просмотра

Для UUID иконки хранить полный исходный `<id>.png`, `<id>.thumb.png` с различимыми рамками и `<id>.template.png`, вырезанный из неизменённого кадра без рамок/подсказок. Это позволяет искать даже при потере исходного снимка просмотра. Условие записывать после успешной подготовки всех файлов; при неуспехе или отмене удалять созданные файлы. В backend повторно проверять существование профиля/отслеживания и режим сессии перед commit; защищаться от устаревшего события предыдущего захвата.

Добавить удаление всех трёх файлов по UUID и очистку иконок при удалении отслеживания/профиля. Декодированные образцы кэшировать до изменения/удаления соответствующей иконки; файлы не декодировать на каждом tick. Перед использованием кэша проверять доступность и метаданные файла, при изменении инвалидировать запись: ручное удаление образца не должно оставлять работающее условие из кэша. Ошибки загрузки возвращать как unavailable, показывать в редакторе/статусе без повторных одинаковых уведомлений каждый tick.

### 4. Сопоставление через OpenCV на backend

Использовать Rust crate `opencv`, только необходимые модули `imgproc` и базовое ядро, без Python процесса и передачи кадров через WebView. Выбранный метод — цветное `matchTemplate` с `TM_SQDIFF_NORMED`; минимальная ошибка `e` преобразуется в техническую оценку `s = 100 * (1 - clamp(e, 0, 1))`. Совпадение при `s >= similarityPercent`; значения по умолчанию — 90%, присутствие. Это показатель сходства, не вероятность распознавания. Проверять конечность исходного результата до clamp. Вырезанный полностью чёрный шаблон с нулевой энергией отклонять с объяснением при добавлении, поскольку нормализация не определена; не считать ошибку отсутствием.

`TM_SQDIFF_NORMED` позволяет сравнивать цветные образцы без вычитания среднего; альтернативный `TM_CCOEFF_NORMED` имеет нежелательный вырожденный случай константного образца. Прямое сравнение bitmap не ищет смещённые позиции и слишком чувствительно к небольшим изменениям. Порог регулируется независимо от допуска RGB пикселей. Маски и multi-scale matching не добавляются.

Документация: [OpenCV matchTemplate и методы сравнения](https://docs.opencv.org/4.5.2/df/dfb/group__imgproc__object.html), [официальный tutorial](https://github.com/opencv/opencv/blob/5.x/doc/tutorials/imgproc/histograms/template_matching/template_matching.markdown), [Rust bindings и Windows установка](https://github.com/twistedfall/opencv-rust/blob/master/INSTALL.md). Зафиксировать совместимые версии Rust crate и native OpenCV при реализации. Использовать воспроизводимую Windows MSVC сборку с native runtime DLL в Tauri bundle; clang и заголовки нужны разработчику/CI, установка OpenCV на машине пользователя не требуется. Проверить установленный release на системе без OpenCV в PATH.

### 5. Один кадр на опрос с сохранением быстрого пути пикселей

Заменить контракт чтения одних точек на пакет визуальных запросов и результатов, идентифицированных UUID. `EngineCore` продолжает владеть фазами и выдавать jobs; OpenCV и DXGI остаются за границей state machine. Пакет включает только элементы отслеживаний, находящихся в `Polling`.

Если пакет содержит только пиксели, оставить нынешнее компактное чтение. При наличии иконок получить один DXGI texture, скопировать нужные прямоугольники и точки из него в переиспользуемые staging buffers, затем выполнить сопоставления в CPU. Не вызывать `read_pixels` и отдельный `capture_frame` последовательно: кадр между вызовами может смениться. Для каждого отслеживания AND всех пикселей и всех предикатов иконок; `unavailable` не инвертировать в `absent`. Когда screen недоступен, пропускать визуальную проверку; успешное повторное использование последнего DXGI кадра при отсутствии desktop changes допустимо по существующей логике, но после access loss старые данные недействительны.

Пауза, активность игры, очередь, задержка и resume сохраняют существующий жизненный цикл. Иконки не опрашивать в задержке, очереди или cooldown. Изменение параметров входит в следующий опрос, а поставленное действие не перепроверяется. Срок 50 мс сохраняется как расписание, без параллельного накопления устаревших jobs при перегрузке.

Альтернатива — полный readback всего монитора на каждый tick — проще, но создаёт избыточные копии и ухудшает существующий быстрый путь пикселей. Нужен замер ROI readback + matching с несколькими иконками и большими областями до признания реализации готовой.

### 6. Общий редактор, отдельные параметры строк

`PixelsSection` сохраняет заголовок варианта и добавляет две независимые кнопки. Рядом с таблицей пикселей показывать список иконок с миниатюрой, признаком присутствия, порогом и удалением. Общее пустое состояние показывать только когда пусты оба списка. Вариант «Хоткей» скрывает обе группы и кнопки. Немедленные мутации не должны сбрасывать черновик имени/задержек.

Viewer расширить discriminated payload маркера: точка либо две области. Рамки поиска и образца различаются цветом/подписью, имеют image-relative positioning и отражают исходный снимок, не текущее найденное положение. Сохранить переиспользование окна, обработку готовности и закрытие по клику/клавише. Иконки используют тот же путь просмотра и ошибок миниатюр.

## Risks / Trade-offs

- [Изменения фона, анимация, затемнение или UI scale] → пользователь выделяет плотный образец и регулирует порог; фиксированный размер явно описан в помощи.
- [Стоимость больших областей при 50 мс] → ROI readback, кэш образцов, переиспользование буферов и замеры p95 на Windows; не скрывать пропуски срока и не применять старые результаты к новому состоянию.
- [OpenCV усложняет сборку и размер поставки] → минимальный набор модулей, фиксированные native версии, документированный toolchain и smoke test чистой установки.
- [Ошибку можно принять за отсутствие] → результат проверки имеет отдельное состояние unavailable; оба предиката при ошибке не проходят.
- [Потеря файлов или смена разрешения] → проверять границы каждого запроса и показывать ошибку соответствующей иконки; повторное добавление создаёт корректный образец.

## Migration Plan

Добавить `icons` с default пустого массива без повышения версии конфигурации и без изменения старых pixel UUID/файлов. Проверить загрузку старых конфигураций и round-trip новых, сохранение хоткеев и состояния запуска. Сначала обеспечить dependency build/runtime, затем модель/файлы, захват/UI, matching и engine, после этого проверить installed release. Перед ручным downgrade сохранять резервную копию конфигурации и файлов: прежняя версия не понимает иконки и при записи может потерять их настройки. Автоматическую поддержку downgrade не вводить.
