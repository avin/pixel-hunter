# Design

## Context

См. `proposal.md`. У отслеживания одно действие: Rust `ActionKind` — это `KeySequence`, JSON с тегом `type`, рядом лежит `sound`. Фронтенд выбирает тип в `actionTypes` и рисует его `Editor`. Движок ставит в очередь `Job { ticket, tracker_id, action }` и вызывает `keyboard::run_action`, который умеет только последовательность клавиш. Имя процесса лежит на профиле (`process_name`) и в сессии поллера, но в задание не копируется.

Рабочий разрыв в PoeLifer (`networkutil.cpp`, `DisconnectNetworkConnections`): найти PID по имени exe, прочитать IPv4-таблицу `TCP_TABLE_OWNER_PID_ALL` и для строк этих PID в состояниях established, SYN sent и SYN received вызвать `SetTcpEntry` с `MIB_TCP_STATE_DELETE_TCB`, копируя адреса и порты как есть. Release-сборка pixel-hunter уже запрашивает права администратора; без них `SetTcpEntry` не выполняется.

## Goals / Non-Goals

**Goals:**

- Тот же набор соединений и тот же способ обрыва, что в PoeLifer.
- Выбор строк таблицы проверяется без реальной сети и без прав администратора.
- Имя процесса фиксируется в момент постановки задания в очередь.

**Non-Goals:**

- Глобальная горячая клавиша дисконнекта из PoeLifer.
- IPv6, UDP, слушающие сокеты и прочие состояния TCP.
- Новый запрос UAC. Повышение прав остаётся как в `admin-elevation`.
- Поднятие `CONFIG_VERSION`: старый JSON по-прежнему десериализуется.

## Decisions

### 1. Вариант действия без полей

`ActionKind::NetworkDisconnect` — unit-вариант internally tagged enum. В файле профиля это `{ "type": "networkDisconnect", "sound": { ... } }`. `is_empty` для него возвращает `false`; `normalize` и `validate` ничего не делают со звуком сверх уже существующей проверки `SoundSettings`.

На фронтенде `Action` — дискриминированное объединение с тем же тегом. В `actionTypes` метка «Разрыв сетевого соединения». `Editor` — текст без полей: «При срабатывании обрываются TCP-соединения процесса профиля.» `createDefault` не копирует шаги; звук по-прежнему переносит `ActionSection`.

Альтернатива — хранить имя процесса внутри действия. Отклонена: процесс принадлежит профилю, а смена процесса должна действовать на следующее срабатывание без пересохранения действия.

### 2. Снимок имени процесса в `Job`

`Job` получает `process_name`. `EngineCore::tick` принимает текущее имя профиля и кладёт его в задание вместе с клоном действия. Поллер передаёт `session.process_name`. Уже стоящее в очереди задание не читает профиль повторно.

Исполнитель получает `&Job`, а не только `&Action`. `play_action` по-прежнему сначала запускает звук, затем выполняет действие. Диспетчеризация уходит из `keyboard::run_action`: последовательность клавиш остаётся там и имя процесса игнорирует, разрыв вызывает модуль сети.

### 3. Обрыв как в PoeLifer, поиск PID — по имени exe

Чистая функция решает, какие строки оборвать: владелец входит в набор PID, состояние — established, SYN sent или SYN received. Адаптер Windows:

1. Снимок процессов через Toolhelp (`CreateToolhelp32Snapshot`). В набор попадают все PID, у которых `szExeFile` совпадает с именем профиля без учёта регистра. Пустое имя — пустой набор.
2. `GetExtendedTcpTable` для `AF_INET` и `TCP_TABLE_OWNER_PID_ALL`, без сортировки. Если между запросом размера и чтением таблица выросла, чтение повторяется, пока хватает буфера, не больше трёх попыток.
3. Для каждой выбранной строки — `SetTcpEntry` со структурой `MIB_TCPROW`: локальный и удалённый адрес и порт копируются без перестановки байт, состояние — `DELETE_TCB`.

Ошибка чтения таблицы или отдельного `SetTcpEntry` пишется в лог, цикл по остальным строкам продолжается, функция завершается успешно. Пауза отслеживания и очередь от этого не зависят: `play_action` и так вызывает `ActionDone` после возврата.

Поиск PID через `EnumProcesses` и `GetModuleBaseName`, как в PoeLifer, отклонён: там потолок в 1024 процесса и `OpenProcess` с правами, которых может не быть у части процессов. Имя exe из Toolhelp — тот же критерий, что `GetModuleBaseName`, и тот же, что уже использует `processes::exe_name`.

### 4. Полнота отслеживания зависит от типа

`Action::is_empty` — единственное правило на бэкенде: пустая последовательность клавиш пуста, разрыв сети — нет. `missing_part` и остановка при неполноте уже опираются на него.

На фронтенде `RunToggle` больше не читает `action.steps` вслепую. Та же развилка в `fakeBackend`: у `networkDisconnect` нет `steps`, и текущая проверка `action.steps.length` сломает и сохранение, и запуск.

### 5. Подтверждение смены типа

Select остаётся управляемым: значение — тип текущего действия. Если у «Нажатия клавиш» есть хотя бы один шаг и пользователь выбирает другой тип, `ActionSection` открывает `AlertDialog` по образцу `DeleteTrackerDialog`: заголовок «Сменить тип действия?», текст о том, что шаги нажатий будут удалены, кнопки «Отмена» и «Сменить». До подтверждения действие не пишется. Отказ и закрытие диалога оставляют прежний тип. Пустая последовательность и уход с разрыва сети меняют тип сразу. В обоих случаях звук копируется в `createDefault` нового типа.

## Risks / Trade-offs

- [Без прав администратора `SetTcpEntry` молча не обрывает соединения] → release уже повышает права. В debug сбой только логируется; отдельный UAC не добавляется.
- [Только IPv4 TCP, как в PoeLifer] → игра, сидящая на IPv6 или UDP, не будет сброшена. Это принятое ограничение образца.
- [Обрываются все процессы с тем же именем exe, не только активное окно] → так делает PoeLifer; вторая копия игры тоже потеряет подходящие соединения.
- [`DELETE_TCB` рвёт соединение сбросом, а не штатным FIN] → это и есть нужный эффект. Слушающие и полузакрытые сокеты не трогаем.
- [Профиль с `networkDisconnect`, открытый старой сборкой, не прочитается] → отката данных нет. Старые профили эта сборка читает без перезаписи.

## Migration Plan

Файлы версии 1 не переписываются. Откат — предыдущая сборка; действия нового типа в уже сохранённых профилях она не откроет.
