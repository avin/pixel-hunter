# Design

## Context

Мотивация описана в `proposal.md`. `KeyStep` сейчас содержит `id`, `combo` и `delayBeforeMs`. Исполнитель `key_sequence.rs` вызывает `bell(rng, HOLD_MS)` после key-down основной клавиши; `HOLD_MS` равен 40–90 мс. `bell` использует три случайных слагаемых с концентрацией около середины. Модификаторы нажимаются перед основной клавишей и отпускаются после неё, с отдельными интервалами 15–35 мс.

В таблице `KeySequenceEditor` строки `StepRow` уже редактируют задержку через `StepDelay`, который использует проверку диапазона из `src/lib/delayRange.ts`. Действие сохраняется целиком через существующий `action_update`. Исполнитель обрабатывает задания последовательно и завершает начатую последовательность даже после паузы.

Основная спецификация сейчас запрещает настройку удержания; delta явно заменяет это правило. В существующем требовании добавления шага также есть несоответствие: текст и frontend задают задержку 100–200 мс, сценарий и backend-default — 300–600 мс. Эта отдельная задержка не меняется в данном предложении; добавление default удержания описывается отдельным требованием.

## Goals / Non-Goals

**Goals:** единый контракт диапазона на всём пути от таблицы до исполнителя, совместимость со старыми конфигурациями, сохранение существующего распределения длительностей по умолчанию.

**Non-Goals:** изменение интервалов модификаторов, записи клавиш, глобальных хоткеев запуска/паузы и семантики прерывания уже начатого действия.

## Decisions

### 1. Обязательный диапазон в модели, default при отсутствии поля

Добавить `hold_ms: DelayRange` в Rust `KeyStep` с отдельным serde-default 40–90, и обязательное `holdMs: DelayRange` в TypeScript. Границы — целые миллисекунды `0..=u32::MAX`, `min <= max`, как у существующих диапазонов. Равные границы дают фиксированное удержание; 0–0 допустим. Не использовать `DelayRange::default()`, который задаёт 100–300 мс.

Backend всегда возвращает заполненное поле, а новые frontend-шаги создают собственный объект `{ min: 40, max: 90 }`. Старый JSON без поля дополняется при десериализации; явные некорректные значения не заменяются default. Проверка удержания включается в `KeySequenceAction::validate`; нормализация первого шага не удаляет удержание. Обновить fake backend и фикстуры под тот же контракт.

Альтернатива — optional поле с fallback в каждом потребителе — разносит правила совместимости между UI и исполнителем. Отдельная миграция файла не нужна: serde решает отсутствие поля без смены формата всей конфигурации.

### 2. Сохранить алгоритм исполнения и заменить его входной диапазон

Передавать границы `step.hold_ms` в существующий `bell` вместо `HOLD_MS`. Измеряемое удержание — от key-down основной клавиши до её key-up; модификаторы остаются нажатыми на протяжении этого времени. Их дополнительные интервалы 15–35 мс сохраняются. Следующий шаг начинается после отпускания всего сочетания и своей задержки.

Альтернатива — равномерное распределение — меняет прежний характер коротких нажатий без необходимости. Общий диапазон для всего действия не удовлетворяет независимой настройке строк.

### 3. Отдельная колонка с диапазоном в каждой строке

Добавить «Удержание, мс» и пояснение о времени до отпускания основной клавиши. Переиспользовать логику редактирования `StepDelay`, параметризовав подписи и доступные имена для различения задержки и удержания (например, «Удержание шага 1, минимум»). Держать локальные промежуточные значения и показывать ошибки без сохранения некорректного диапазона, как сейчас для задержки. Валидное изменение сохранять по существующему механизму редактора.

Колонка видна и у первого шага. Перезапись сочетания через spread сохраняет диапазон; удаление другого шага меняет только позиционную задержку. Подобрать минимальную ширину таблицы под новую колонку, сохранив существующий горизонтальный скролл. Альтернатива — отдельный диалог — скрывает индивидуальную настройку из таблицы и усложняет работу с последовательностью.

## Risks / Trade-offs

- [Длительное удержание занимает последовательный исполнитель и задерживает другие действия] → сохранить контракт завершения начатого действия; пояснить пользователю назначение диапазона. Прерывание не добавляется в этом изменении.
- [При аварийном завершении процесса удерживаемая клавиша может остаться нажатой] → существующее ограничение ввода сохраняется; обычное завершение шага отправляет key-up и отпускание модификаторов. Гарантии cleanup при аварии не расширяются.
- [Новая колонка не помещается на узком экране] → использовать существующий горизонтальный скролл и проверить доступность всех полей и команд.
- [Перепутаны default удержания и задержки] → отдельная константа default удержания, тест старого JSON и тест нового шага.

## Migration Plan

1. Выпустить согласованные backend/frontend изменения; старые конфигурации без `holdMs` читаются с 40–90 мс.
2. При обычном сохранении поле записывается в JSON; проверить повторную загрузку индивидуальных значений.
3. Откат к предыдущей версии вернёт хардкод 40–90 мс: дополнительное поле игнорируется старой serde-моделью и может быть потеряно при её следующем сохранении. Перед откатом сохранить копию конфигурации, если требуется восстановить настройки удержания.
