# Design

## Context

См. proposal.md. Сейчас `capture` в `pixel_capture.rs` после `capture_frame` делает следующее строго по порядку: `play_shutter`, `to_rgb_image`, `save_png` (`CompressionType::Fast` и `FilterType::Adaptive`), `thumbnail`, и только затем `show_picker`. `show_picker` сворачивает игру и вызывает `open`: если окна `screen-overlay` нет, создаётся WebView; если есть, `navigate` заново загружает страницу. Страница выбора берёт `profileId` и `pixelId` из query и не рисует снимок, пока не ответят `screenshots_dir` и `img.onLoad`.

Окно просмотра снимка (`screenshot-viewer`) уже живёт отдельно: скрытое, переиспользуемое, без `navigate`. Это изменение его не трогает.

Создание окна WebView из синхронной команды на Windows deadlock-ается; сессия захвата уже создаёт окно со своего фонового потока. Так же создаётся подготовленное окно.

## Goals / Non-Goals

**Goals:**

- Звук затвора и уже нарисованный снимок с курсором-крестиком появляются одним шагом.
- Холодный старт окна, страницы и WAV затвора проходит во время ожидания игры и отсчёта.
- Между затвором и показом окна нет записи файла, миниатюры и загрузки страницы.

**Non-Goals:**

- Менять 10 с ожидания, 3 с отсчёта, DXGI-снимок, координаты клика и команды `pixel_capture_start` / `pixel_capture_pick` / `pixel_capture_cancel`.
- Показывать выбор поверх ещё не свёрнутой игры.
- Сжимать уже записанный PNG повторно и менять окно просмотра снимка.

## Decisions

### 1. Окно выбора создаётся в начале сессии и больше не уничтожается

В старте сессии, параллельно с `wait_for_game` и отсчётом, фоновый поток вызывает подготовку. Она:

- один раз создаёт скрытое окно `screen-overlay` с `index.html?view=picker` без идентификаторов пикселя;
- инициализирует WAV затвора, не проигрывая его;
- ждёт, пока страница сообщит, что она загружена и каталог снимков уже известен.

Сессия доходит до `capture_frame` только после этой готовности. Отмена во время ожидания по-прежнему не делает снимок и не играет затвор; поток подготовки при этом дожидаются, окно остаётся скрытым.

Показ не вызывает `navigate` и не создаёт окно заново. Закрытие выбора скрывает окно и сбрасывает показанный кадр. `OverlayClosed` по-прежнему шлётся только при `Destroyed`. Окно уничтожается вместе с главным окном, по тому же приёму, что и `screenshot-viewer`.

Если окно не удалось создать или страница не сообщила о готовности, сессия завершается ошибкой до затвора и без показа. Ожидание готовности ограничено, чтобы сломанная страница не держала сессию бесконечно; запас совпадает по порядку с уже существующими 10 с ожидания игры.

Альтернатива — создать окно при старте приложения. Отложена: окно нужно только захвату, а ожидание игры и так длиннее холодного старта WebView.

### 2. Затвор играет в момент показа, после сворачивания игры

Порядок после готового кадра:

1. Записать файл снимка способом из решения 3 и отдать его уже загруженной странице.
2. Дождаться, пока страница декодирует кадр, пока окно ещё скрыто. Ошибка декодирования отменяет захват до затвора, скрывает окно и удаляет файл.
3. Свернуть игру.
4. Одним шагом проиграть затвор и показать окно поверх основного монитора.

Пустое окно не показывается: `Screenshot` и сейчас держит `img` невидимым до `onLoad`, а само окно остаётся скрытым до этого `onLoad`. `play_shutter` больше не вызывается до записи файла и до `show`.

Сворачивание эксклюзивного полноэкранного режима нельзя прогреть заранее: снимок должен застать игру ещё на экране. Поэтому оно стоит до затвора, а не между затвором и окном.

### 3. Файл снимка пишется без подбора фильтра PNG

`save_png` с `FilterType::Adaptive` для полного кадра монитора перебирает фильтры каждой строки. Это и есть многосекундная работа между затвором и окном, вместе с созданием WebView.

Полный снимок пишет отдельная функция: PNG с фильтром None и stored-блоками deflate, без перебора фильтров и без усилия сжатия. Это по-прежнему `{profileId}/{pixelId}.png`, его читают и выбор точки, и просмотр. Пиксель для цвета клика по-прежнему берётся из `Frame` в памяти.

Миниатюра строится в момент выбора точки, не до показа. Для маленького кадра остаётся текущий `save_png`.

Альтернатива — оставить `PngEncoder` и сменить только фильтр на `No`. Быстрее Adaptive, но deflate полного кадра всё ещё стоит на пути к затвору. Альтернатива — BMP или свой протокол в память. Меньше диска, но ломает уже существующий путь `convertFileSrc` к `.png`.

Несжатый PNG больше сжатого. Для этого изменения размер файла приемлем: повторное сжатие после показа снова поставило бы тяжёлую работу рядом с выбором и могло бы подменить файл у открытого изображения.

### 4. Страница выбора получает кадр событием

`ScreenOverlayApp` в режиме `picker` монтирует оболочку, которая при подготовке только получает каталог снимков и сообщает о готовности. Идентификаторы приходят событием уже после записи файла, без смены URL. Повторный захват использует тот же документ: новый `pixelId` даёт новый URL снимка.

Координаты, крестик, Esc и `pixel_capture_pick` не меняются.

## Risks / Trade-offs

- [Сворачивание полноэкранной игры само занимает секунды] → затвор не играет, пока окно не показано. Пауза возможна после отсчёта, но не после звука. Прогреть этот переход нельзя.
- [Несжатый PNG занимает десятки мегабайт на 4K] → файл остаётся обычным PNG для просмотра и удаления. Повторное сжатие в это изменение не входит.
- [Подготовка не успела за отсчёт] → снимок ждёт готовности в пределах общего запаса; по истечении захват падает с ошибкой до затвора.
- [Скрытый WebView не дорисовывает кадр] → показ завязан на декодирование изображения, как у просмотра снимка, а не на следующий animation frame.

## Migration Plan

Формат каталога снимков и конфигурация не меняются. Откат — вернуть прежний порядок сессии и создание окна по требованию.
