# Design

## Context

Мотивация и область изменения описаны в `proposal.md`. `TrackerForm` использует стабильный контроллер `@avinlab/react-form`, строковый черновик, `baseline` и `useBlocker`. Сейчас запись запускается только обработчиком заблокированного перехода, а поля выключаются на всё время `isLoading`. `useErrorReveal` раскрывает ошибки после blur или попытки выхода; тесты закрепляют именно это поведение.

`tracker_update` принимает только имя, диапазон задержки и паузу; Rust обновляет эти поля на актуальной конфигурации через `ConfigStore`. RTK Query инвалидирует профиль и обновляет список после мутации. Поэтому новый черновик нельзя заменять входящим объектом `tracker`, а сохранять весь старый объект отслеживания не требуется.

`TrackerPage` размещает две секции в `grid-rows-2`. Секции уже имеют собственную прокрутку и ограничения `min-h-0`. В верхней панели `ProfilePage` изменение/удаление профиля и создание отслеживания находятся в одной группе `gap-1`. Готовый `ui/separator` поддерживает вертикальную ориентацию. Хранения настроек компоновки в frontend сейчас нет.

## Goals / Non-Goals

**Goals:**
- Один поток сохранения для debounce и выхода, без параллельных записей настроек и без потери нового ввода.
- Отдельные состояния фоновой записи и выхода: первая позволяет ввод, второе фиксирует черновик и адрес перехода.
- Сохранение пропорции независимо от пиксельных размеров окна и конфигурации игровых профилей.

**Non-Goals:**
- Менять правила сохранения пикселей, действий, запуска или редактирования профиля.
- Добавлять кнопку сохранения, синхронизацию компоновки между устройствами, миграцию Rust-конфигурации или обработку закрытия окна ОС. Текущая гарантия выхода относится к навигации приложения.
- Менять глобальное раскрытие ошибок всех форм: новое поведение ограничено настройками отслеживания.

## Decisions

### 1. Debounce 500 мс для единого черновика настроек

Один таймер отсчитывает 500 мс от последнего изменения любого поля имени/задержек. Это исходное значение, выбранное для предложения. Изменение отменяет старый таймер; отмена нужна также при навигации и размонтировании. Blur и Enter не сокращают ожидание. Сравнение выполняется по нормализованному payload (trim имени и числовые задержки), чтобы пробелы вокруг имени и равнозначные числа не создавали лишних записей.

Альтернативы: сохранение каждого символа создаёт избыточные записи; throttle может записать промежуточное значение в середине ввода; отдельные таймеры полей усложняют атомарную проверку диапазона и существующий контракт общей записи.

### 2. Последовательные записи с подтверждением отправленного снимка

Владелец формы хранит актуальный строковый снимок, последний подтверждённый нормализованный payload, снимок выполняемого запроса, момент последнего изменения и состояние ошибки. Состояние выполнения должно участвовать в реактивном принятии решений; один `ref` без уведомления React не должен оставлять ожидающую запись незапущенной.

Общий механизм сохранения получает актуальные значения императивно через `form.values`, проверяет их и отправляет только payload настроек. Одновременно допускается один `tracker_update` из этой формы. По успеху подтверждается отправленный payload, а не значения на момент ответа; контроллер формы не сбрасывается. После завершения проверяется свежий черновик: если он изменён и корректен, запись отправляется после оставшейся части debounce либо сразу, если 500 мс уже истекли. Не следует хранить очередь всех промежуточных снимков: сохраняется актуальный черновик.

При ошибке автоматический повтор того же снимка останавливается до нового ввода или попытки выхода; ошибка остаётся видимой. Для нового ввода снова действует debounce. Состояние «Сохранение…» доступно и в фоне; поля выключаются только при выходе, а не при любом `isLoading`.

Альтернатива с параллельными мутациями требует порядка записи на backend и может сохранить устаревшее значение последним. Отключение ввода на каждой фоновой записи создаёт заметные остановки печати.

### 3. Выход использует тот же механизм с немедленным завершением

`useBlocker` продолжает блокировать переход при несохранённых изменениях или активной записи. Первый адрес фиксируется существующей координацией `WorkspaceNavigationContext`. При выходе отменяется таймер, включается `isLeaving` и замораживается ввод. Некорректный черновик показывает ошибки, фокусирует первое ошибочное поле и сбрасывает переход.

Если запрос уже идёт, обработчик ждёт его завершения без дублирования. При успешной записи сравнивает подтверждённый payload с замороженным черновиком и при необходимости записывает последний без debounce. При ошибке записи переход сбрасывается, значения остаются доступны и причина показывается. `proceed()` вызывается один раз только когда последний payload подтверждён. На размонтировании таймер и подписки освобождаются; уже отправленный запрос не считается отменённым лишь из-за очистки эффекта, но его ответ не должен менять другую форму.

Сохранение только на debounce без завершения при выходе теряет изменения при быстрых переходах; отдельная реализация сохранения для перехода создаёт гонки и дублирование.

### 4. Проверка при вводе остаётся локальной к TrackerForm

Переиспользовать `validateTracker`, `delayRangeError` и `millisecondsError`, сохраняя предел `u32` и существующую группировку ошибок диапазона. В render показывать ошибки изменённых полей без ожидания blur, используя единый результат `useFormValidation`; перед фактической записью синхронно проверить именно актуальный отправляемый снимок. Результат `unvalidated` не считать валидным. При ошибке порядка границ подсвечивать обе границы; описание связывать через `aria-describedby`, состояние через `aria-invalid` и `data-invalid`.

Не менять общий `useErrorReveal` для остальных форм: их сценарии раскрытия ошибок не входят в запрос. Программная нормализация поля после ответа не нужна: сохранённый payload нормализуется, строковый ввод сохраняется.

### 5. Разделитель хранит долю высоты, а измеряет геометрию только при взаимодействии

Заменить фиксированную сетку двумя гибкими строками и отдельной строкой ручки между ними. Доля `p` относится к доступной высоте двух секций без ручки и внешних отступов; строки задаются пропорциональными долями `p` и `100-p`. Исходное значение 50. Предварительный диапазон доли — 20–80%; дополнительно ограничивать перетаскивание текущими минимальными высотами секций, достаточными для заголовков и команд. На уменьшении окна применять ограничения к отображаемой геометрии, не перезаписывая сохранённое предпочтение пользователя; возвращать предпочтение, когда место появляется.

Отдельный компонент разделяемой области в каталоге `TrackerPage` владеет взаимодействием и состоянием пропорции. Pointer Events с захватом указателя обеспечивают продолжение перетаскивания за пределами ручки; вертикальное смещение пересчитывается в процент текущей доступной высоты. По завершении отпускания или отмене захвата корректно заканчивать взаимодействие и сохранять последнюю принятую пропорцию. Область перетаскивания не рисует линию: при наведении меняется только указатель на `row-resize`. Во время перемещения текст не выделяется; индикатор клавиатурного фокуса сохраняется.

Ручка фокусируема с `role="separator"`, горизонтальной ориентацией, доступным названием и процентными `aria-valuenow/min/max`; стрелки вверх/вниз меняют долю на 1 процентный пункт. Заголовки и команды обеих секций остаются доступны при больших таблицах, пустых состояниях и захвате пикселя.

Альтернатива: новая библиотека панелей увеличивает зависимости для единственного разделителя; хранение пикселей нарушает требование адаптации к высоте окна.

### 6. Общая локальная настройка в localStorage

Использовать версионированный ключ `pixel-hunter.tracker-editor.pixels-height-percent.v1`. Общая настройка для всех отслеживаний — допущение предложения, соответствующее пользовательской настройке рабочей области. Читать конечное число в пределах 20–80; отсутствующие, пустые, повреждённые и вне диапазона значения заменять 50. Записывать по окончании перетаскивания и после клавиатурного изменения. Ошибка доступа к хранилищу не должна мешать перемещению ручки: в текущем сеансе остаётся значение в памяти.

Настройку не включать в данные профиля и не отправлять через `tracker_update`. Альтернатива — индивидуальное значение для каждого отслеживания — создаёт ненужную связь UI-предпочтения с доменными сущностями.

### 7. Разделитель команд использует существующий UI-компонент

В `ProfilePage` добавить `Separator orientation="vertical"` с горизонтальными отступами между группой профиля и кнопкой создания. Разделитель и кнопка условно показываются вместе только для непустого списка. Семантика декоративная; порядок фокуса и обработчики кнопок сохраняются.

## Risks / Trade-offs

- [Старый ответ или refetch стирает новый ввод] → стабильный контроллер формы, подтверждение отправленного payload и отсутствие автоматического `setValues(tracker)`.
- [Выход конкурирует с таймером или текущей записью] → единый поток, отмена таймера и ожидание запроса перед сравнением последнего payload.
- [Сбой вызывает цикл запросов и уведомлений] → остановить повтор без нового ввода или выхода; оставить видимую причину.
- [Подсветка появляется при временно пустом поле] → это соответствует проверке по мере ввода; исправление сразу снимает ошибку без перемещения фокуса.
- [Ограничения высоты нарушают предпочтение на маленьком окне] → временно ограничить отображение, сохранять процент предпочтения и проверить окно 900 × 600 и масштаб Windows 150%.
- [Хранилище UI недоступно] → безопасное чтение/запись и работа с текущим значением в памяти.
- [Старые тесты ожидают сохранения только на выходе и ошибки после blur] → обновить эти ожидания и оставить проверки блокировки выхода и сохранности пикселей/действий.

## Migration Plan

Миграция данных не требуется: backend и формат профилей сохраняются. Новая настройка UI получает 50/50 при первом открытии. Откат frontend возвращает сохранение при выходе и равные строки; неиспользуемый ключ localStorage безопасно остаётся. После реализации выполнить поведенческие тесты и сборку, затем проверить компоновку и восстановление пропорции в приложении.
