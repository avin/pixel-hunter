# Proposal

## Why

Когда условия по пикселям выполнены, отслеживание должно что-то сделать в игре. Первое и пока единственное действие — серия нажатий клавиш и сочетаний с паузами между ними. Позже появятся другие действия со своими настройками, поэтому выбор типа действия и его редактор нужно сразу сделать расширяемыми.

Изменение опирается на `add-app-foundation`. Выполнение действия по условию подключает `add-tracking-engine`.

## What Changes

- У отслеживания появляется действие с выбором типа через select. Каждый тип настраивается в собственной форме.
- Тип «Нажатие клавиш»: список шагов.
  - Каждый шаг — клавиша или сочетание, записанное по кнопке «съём нажатия».
  - Перед каждым шагом, кроме первого, задаётся диапазон задержки в миллисекундах.
  - Шаги можно перезаписывать и удалять.
- Исполнитель последовательности в Rust:
  - случайная задержка из заданного диапазона перед каждым шагом;
  - эмуляция нажатия аппаратными скан-кодами через `SendInput` без инъекции в процесс игры;
  - зашитое в коде удержание клавиш и интервалы между модификаторами с естественным разбросом.

## Capabilities

### New Capabilities

- `tracker-actions`: выбор типа действия отслеживания и расширяемая модель типов.
- `key-sequence-action`: настройка и выполнение последовательности нажатий клавиш.

### Modified Capabilities

Нет.

## Impact

- `src-tauri`:
  - крейт `rand`;
  - фичи `windows`: `Win32_UI_Input_KeyboardAndMouse` и `Win32_Media` для `timeBeginPeriod`;
  - модели `Action`/`KeySequenceAction`, таблица скан-кодов, исполнитель, команды `action_update` и `key_codes_list`.
- `src`: секция действия на `TrackerPage` с реестром типов действий, редактор последовательности и компонент записи нажатия.
- Модель `Tracker` получает поле `action` со значением по умолчанию, существующие конфигурации читаются без миграции.
