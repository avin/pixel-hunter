# Design

## Context

После `add-app-foundation` есть профили и отслеживания в `ConfigStore` (Rust), RTK Query поверх команд Tauri и `TrackerPage`. Здесь добавляется первый код, работающий с экраном. Модуль захвата нужен и движку из `add-tracking-engine`, поэтому проектируется как общий.

Ограничения из обсуждения:
- никакой инъекции в процесс игры;
- только основной монитор;
- координаты — физические пиксели основного монитора, (0, 0) в левом верхнем углу;
- overlay поверх игры не используется.

## Goals / Non-Goals

**Goals:**
- Надёжный снимок основного монитора через DXGI Desktop Duplication, в том числе для полноэкранных игр, где GDI возвращает чёрный кадр.
- Точный выбор пикселя при любом масштабе Windows.
- Один модуль захвата для снимка и для движка.

**Non-Goals:**
- Несколько мониторов, повёрнутые мониторы, HDR-тонмаппинг.
- Лупа и увеличение при выборе точки.
- Повторный выбор точки для существующего пикселя (удаляется и добавляется заново).

## Decisions

### 1. Модуль `screen`: DXGI Desktop Duplication основного монитора

`PrimaryScreen` создаёт `ID3D11Device` на адаптере основного монитора. Нужный `IDXGIOutput1` находится сравнением `DXGI_OUTPUT_DESC.Monitor` с `MonitorFromPoint((0,0), MONITOR_DEFAULTTOPRIMARY)`. Затем вызывается `DuplicateOutput`.

API модуля:
- `capture_frame() -> Frame`: полный кадр BGRA с шириной и высотой, для снимка;
- `read_pixels(&[(x, y)]) -> Vec<Rgb>`: для движка. Каждая точка копируется через `CopySubresourceRegion` прямоугольником 1×1 в свой столбец staging-текстуры N×1. На CPU отображается только N пикселей, даже если точки разбросаны по углам экрана.

Последний полученный кадр хранится как текстура: `AcquireNextFrame` с таймаутом отдаёт кадр только при изменениях экрана, поэтому при `DXGI_ERROR_WAIT_TIMEOUT` используется прежний кадр. При `DXGI_ERROR_ACCESS_LOST` (смена режима, переключение полноэкранного режима игры, окно UAC) дубликатор пересоздаётся. Пока пересоздание не удалось, вызовы возвращают ошибку, а не устаревшие данные.

Альтернативы:
- GDI `BitBlt`: проще, но чёрный кадр в эксклюзивном полноэкранном режиме.
- Windows.Graphics.Capture: требует выбора окна или монитора и показывает жёлтую рамку на Windows 10.

### 2. Сценарий захвата в Rust, статус через события

Команда `pixel_capture_start(profileId, trackerId)` запускает async-задачу. Повторный запуск при активной сессии возвращает ошибку. Этапы:

```
waitingForGame (до 10 000 мс, опрос активного окна каждые 100 мс)
   -> countdown (3 000 мс)
   -> snapshot: capture_frame + звук затвора + PNG на диск
   -> ShowWindow(hwnd игры, SW_MINIMIZE) -> окно выбора точки
   -> picking -> pixel_capture_pick(x, y) | pixel_capture_cancel()
```

Статус уходит событием `pixel-capture://status` с полями `phase`, `remainingMs`, `reason`. Главное окно показывает его и кнопку отмены (`pixel_capture_cancel`).

Определение активного процесса (`GetForegroundWindow`, `GetWindowThreadProcessId`, `QueryFullProcessImageNameW`, сравнение имени exe без учёта регистра) выносится в общий модуль `foreground`. Его переиспользует движок.

Если игра потеряла фокус в течение 3 секунд, снимок всё равно делается: требования перепроверки нет.

### 3. Хранение снимков

Путь: `<app_data_dir>/screenshots/<profileId>/<pixelId>.png`, рядом миниатюра `<pixelId>.thumb.png` шириной 320 px. Идентификатор пикселя генерируется до снимка.
- При выборе точки файлы остаются, пиксель записывается в `ConfigStore`.
- При отмене или ошибке файлы удаляются.

PNG кодируется крейтом `image` с быстрым сжатием. Цвет выбранной точки берётся из кадра в памяти, а не из перекодированного файла.

Модель: `Tracker.pixels: Vec<Pixel>` с `#[serde(default)]`, где
`Pixel { id, x: u32, y: u32, color: { r, g, b }, condition: "equals" | "notEquals", tolerancePercent: u8 }`.

Удаление пикселя, отслеживания и профиля удаляет соответствующие файлы или каталог `screenshots/<profileId>`. Ошибки удаления файлов логируются и не отменяют удаление из конфигурации.

### 4. Окно выбора точки и просмотра — одно окно Tauri в двух режимах

Окно `screen-overlay` создаётся по требованию:
- без рамки, поверх всех окон, без кнопки в панели задач;
- позиция и размер — физические позиция и размер основного монитора.

URL `index.html?view=picker&...` или `?view=viewer&profileId=...&pixelId=...`. `main.tsx` по параметру `view` рендерит `ScreenOverlayApp` вместо основного приложения. Снимок загружается через asset protocol: `convertFileSrc`, `assetProtocol.scope` на `$APPDATA/screenshots/**`, фича `protocol-asset`.

Один к одному: изображение выводится шириной `naturalWidth / devicePixelRatio` CSS-пикселей от (0, 0). Координаты клика вычисляются чистой функцией `x = clamp(floor(clientX * dpr), 0, width - 1)`, так же для y. Её проверяют unit-тесты для масштабов 100%, 125%, 150%.

Отметка в просмотре — SVG поверх снимка:
- круг толщиной около 3 CSS px;
- две линии креста шириной `1 / dpr` CSS px, выровненные по центру физического пикселя.

`pointerdown` или `keydown` закрывает окно. В режиме выбора Esc вызывает `pixel_capture_cancel`.

Вывод окна на передний план: после сворачивания игры вызывается `set_focus`. Если `GetForegroundWindow` не равен нашему окну, применяется `AttachThreadInput` к потоку текущего активного окна, затем `BringWindowToTop` и `SetForegroundWindow`, затем отсоединение. После выбора точки главное окно показывается и активируется тем же способом.

Альтернатива — заранее созданное скрытое окно, чтобы ускорить показ. Отложена: создание по требованию проще, задержку оценим на практике.

### 5. Звук затвора без файла с лицензией

WAV синтезируется в Rust один раз при первом использовании: два коротких щелчка из шума с экспоненциальным затуханием, около 150 мс, 44.1 кГц, 16 бит, моно. Проигрывается через `PlaySoundW(SND_MEMORY | SND_ASYNC)`.

Альтернатива — готовый CC0-файл в ресурсах. Отложена: синтез избавляет от вопроса лицензии и от бандлинга ресурсов.

### 6. Таблица пикселей

Таблица на `TrackerPage` строится на примитиве shadcn `table`.
- Условие — `select`.
- Допуск — числовое поле, целое 0–100. Сохраняется по `blur` или Enter, если значение корректно; ошибка показывается по контракту skill `react-components`.
- Изменения идут командами `pixel_update` и `pixel_delete`.
- Новый пиксель приходит через инвалидацию тега `Profile` после события `phase: "done"`.

## Risks / Trade-offs

- [Windows не даёт вывести наше окно на передний план] → обход через `AttachThreadInput`. Проверяется в первую очередь на реальной полноэкранной игре. Запасной вариант — мигание в панели задач и подсказка пользователю.
- [Полноэкранная игра долго переключает режим при сворачивании] → снимок делается до сворачивания, поэтому задержка влияет только на появление окна выбора, а не на содержимое снимка.
- [`DXGI_ERROR_ACCESS_LOST` прямо в момент снимка] → до трёх попыток пересоздания, затем отмена захвата с сообщением.
- [Защищённый контент или HDR дают чёрный или пересвеченный снимок] → вне рамок изменения; пользователь видит снимок и может отменить выбор.
- [Размер файлов снимков, 5–15 МБ на 4K] → допустимо для десятков пикселей; миниатюры не дают таблице грузить полные файлы.
