# React-компоненты

Применяй каждое правило ниже к каждому затронутому файлу. Сложный публичный API — skill `react-composition`. Тесты — skill `testing-style`. Формы на `@avinlab/react-form` — skill `avinlab-form`.

## Размещение

- `src/components/ui/` — переиспользуемые примитивы shadcn/ui в lowercase-файлах: `button.tsx`, `card.tsx`.
- `src/components/app/` — каркас приложения: layout, router, sidebar.
- `src/components/pages/` — страницы в `PageName/PageName.tsx`; локальные части страницы держи дочерней папкой: `PageName/Child/Child.tsx`.
- Компонент одного владельца не выноси в `ui/`; в `ui/` переноси только после появления независимых потребителей.
- Компонент импортируй из его файла, не через barrel `index.ts`.
- PascalCase — только для файлов React-компонентов; соседние утилиты именуй строчными именами: `utils.ts`, `navItems.ts`.
- Локальные изображения храни в `images/` внутри папки компонента.

## Код и API

- Пиши function components с именованными экспортами.
- Props объявляй рядом как неэкспортируемый `interface Props`; внешний код может получить тип через `React.ComponentProps<typeof ComponentName>`.
- Обёртка над Base UI расширяет props соответствующего примитива, а обёртка над нативным элементом — его HTML-атрибуты. Остальные атрибуты передавай через `...rest`.
- Валидацию форм веди через `@avinlab/react-form`: его правила, статус и ошибки являются источником истины; для таких форм используй `noValidate`, чтобы браузерная HTML constraint validation не перехватывала отправку и не подменяла библиотечную логику.
- Сложное фокусное, клавиатурное или ARIA-поведение собирай из примитивов `@base-ui/react`; простую семантику оставляй нативной.
- В React 19 передавай `ref` как обычный prop; `forwardRef` нужен только для явной совместимости.
- Собственные boolean-props называй `isX` / `hasX`, публичные колбэки — `onX`; имена DOM/Base UI props сохраняй.
- Классы объединяй через `cn` из `cn`; условные классы передавай вторым и последующими аргументами, без логических выражений внутри одного аргумента.
- Соседние и дочерние файлы импортируй относительно, остальные файлы из `src` — через `@/`.
- Асинхронный контент имеет явные loading, error и empty states; skeleton при загрузке сохраняет структуру layout.

## Текст и доступность

- Интерактивные элементы доступны с клавиатуры и имеют доступное имя; поле формы имеет связанную подпись, подходящие `autoComplete`, `type` и `inputMode`.
- Видимый `focus-visible` и нецветовой индикатор состояния должны сохраняться.
- Ошибку невалидного поля впервые показывай после того, как пользователь изменил значение и снял с поля фокус, либо после попытки отправить форму. Попытка отправки показывает ошибки всех невалидных полей независимо от их предыдущего редактирования и фокуса.
- После первого показа ошибки этого поля обновляй её видимость при каждом изменении значения: валидное значение скрывает ошибку сразу, а последующий возврат к невалидному значению сразу показывает её снова, без ожидания потери фокуса. Этот режим действует до явного сброса формы или загрузки новых начальных значений; успешная отправка сама его не сбрасывает.
- Ошибку поля связывай с ним через `aria-describedby`. После неуспешной отправки переводи фокус на сводку ошибок или первое невалидное поле, если изменение иначе останется незаметным.
- Динамический статус объявляй через подходящий `role="status"` / `role="alert"` и не дублируй его озвучивание.
- Семантика заголовков сохраняет иерархию. Контраст — не ниже 4.5:1 для обычного текста и 3:1 для крупного.

## Стили и layout

- Стили пиши утилитами Tailwind в `className`; варианты shadcn/ui описывай через `cva` из `class-variance-authority`.
- Новые UI-примитивы добавляй через shadcn CLI в `src/components/ui/`; не дублируй уже существующие компоненты.
- Цвета, отступы, типографика, радиусы и тени бери из CSS-переменных темы в `src/index.css`; произвольное значение требует опоры на дизайн.
- Визуальный язык держи сдержанным: градиенты, тени, скругления, отступы и сетки следуют дизайну или явной функции.
- Верстай mobile-first. Значимый layout проверяй на 320, 768, 1024 и 1440 px.
- Изображения имеют размеры или `aspect-ratio`; изображения ниже первого экрана загружаются лениво.
- `memo`, `useMemo` и `useCallback` вводи после профилирования дорогого рендера и измеряй тот же сценарий после изменения.
